# Mechanic-grounded visual law

The complete user correction is binding: feature-only interpretation is insufficient.
Read the scenario, execution plan, mechanics, provider bindings and simulations,
contracts, topology, and proof/evidence before resolving a human experience.

Every scenario has a Scenario Visual Evidence Package with source entry digests
and JSON pointers. Dependencies are not providers. Declared fixtures are not
observed executions. A missing supplier or simulation is unresolved unless its
absence or non-applicability is established by inspecting the relevant boundaries.
Do not invent a retry, fallback, approval, side effect, or external service.

The Event requires ordered, evidence-linked animation beats: what enters, what
is compared or transformed, which responsibility and provider perform the work,
which branch is taken, what evidence emerges, and what remains unchanged.
Input, Event and Outcome retain the distinct-experience law. Human staging is
editorial direction, explicitly separated from facts of execution.

Live generation requires a reviewed mechanics package, exact package digest,
source citations, and distinct phase direction. Missing mechanics, unsupported
provider behavior, feature-only grounding, or stale evidence blocks rendering.
Structural extraction is never visual acceptance. Existing v1 and v2 imagery
has not passed this stronger requirement and is retained as rejected exploration.

Review criteria: scenario fidelity, mechanic fidelity, provider fidelity,
execution fidelity, outcome fidelity, human legibility, animation readiness,
and whether the direction contains specific facts unavailable from Gherkin alone.

This lab reads and snapshots capsule data; it does not execute the source
capsules, mutate the managed estate, or declare managed publication.
