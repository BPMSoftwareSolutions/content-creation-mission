# What is allowed to happen next?

A source-cited editorial pilot for `resolve-governed-scenario-route`.
The accompanying [eight declarations](../declarations/governed-routing.visual-experiences.v1.json)
cover every scenario in the selected feature. Their source hash fixes the exact
document used. They are editorial interpretations, not admitted projections.

The visual grammar is three panels: input, comparison in progress, and the
resulting authorization or evidence. Indigo identifies declared authority,
teal an authorization, amber pending, and coral rejection. Text and distinct
shapes repeat every color meaning. This is proposed art direction, not an
assertion about SideFX's official brand.

## A 60-second explanation

| Time | Image and motion | Narration |
| --- | --- | --- |
| 0–7s | Three source documents appear: outcome, route authority, state snapshot. Route tokens stay stationary. | An outcome has arrived. What is allowed to happen next? The answer comes from declared routes and the supplied state. |
| 7–15s | An outcome label aligns with a declared variant. Cut to a separate undeclared example, ending in rejection evidence. | Resolve the selected variant. An undeclared result does not become a default choice. |
| 15–23s | Declared route lines are outlined. A separate ambiguous example shows two equally emphasized candidates. | Use only the routes that authority declares. Missing and ambiguous routes produce evidence, not a guess. |
| 23–30s | Snapshot sections show products, completed members and recorded iterations. A matching identity strip remains fixed. | State arrives with the request. Resolution reads an immutable snapshot; it does not fetch hidden context. |
| 30–38s | The fan-out outline displays all required member slots. A separate incomplete set keeps its empty slot visible. | A declared fan-out requires every member together. A partial set cannot stand in for the whole. |
| 38–46s | Required convergence slots are compared with existing evidence. A missing slot leaves the PENDING card visible. | Convergence is ready only when every required product is present under the same governing identity. Otherwise, it remains pending. |
| 46–53s | Observed iterations and declared bound sit beside a stationary return arrow. | A return needs remaining authority within its declared bound. Resolving permission never performs the return. |
| 53–60s | One continuation record appears with its route identities and digest labels. Finish on AUTHORIZATION, with all route tokens stationary. | The result is one authorized continuation, pending state, terminal result or rejection—with its lineage intact. Execution is a separate responsibility. |

Timing is an editorial target. Record narration and adjust cuts to the measured
read before claiming a finished 60-second film. Chapters do not assert a runtime
execution order. Alternative outcomes are separate examples.

## First three-frame visual: convergence

**Input.** An abstract document tabletop contains the declared convergence
requirements and an immutable state snapshot. Use labeled product slots. Any
chosen number of slots is explicitly illustrative.

**Event.** Highlight comparisons between requirements and products already in
the snapshot. Match governing identity labels. Do not animate a new product
arriving: this responsibility resolves readiness from supplied evidence.

**Outcome.** One required slot remains empty. The gate stays stationary and is
labeled PENDING. Show the unresolved requirement. A separate all-products-present
variant may say READY, but must still stop before downstream execution.

Provider-neutral candidate prompt:

> Create a clean three-panel explanatory storyboard on an abstract document
> tabletop, labeled INPUT, EVENT and OUTCOME. Show declared convergence
> requirements beside an immutable state snapshot. In the middle panel highlight
> comparisons against products already present, with the same governing identity
> on both documents. In the final panel keep a missing requirement visibly empty
> and show a stationary gate labeled PENDING. Use indigo for authority and amber
> with text and an open-slot shape for pending. No moving execution token, no
> arriving product, no completed downstream task. Tile count is illustrative.

This prompt is a rendering derivative of
`@scenario:resolve-convergence-readiness`, not the scenario's authority.

## Editorial review

All eight source scenario IDs appear exactly once in the declaration collection.
Every experience points to its source scenario and Given, When or Then role.
Unknown concrete instances remain explicit. The comparison colors, objects and
camera behavior are identified as art direction. The draft preserves the
feature's central constraint: route resolution authorizes and never executes.

The pilot demonstrates reusable motifs for resolution, routing, admission,
validation, composition, convergence and rejection. These are editorial
assignments; no statistical estate taxonomy has been inferred. Extend the
corpus from further source documents, then revise the taxonomy using observed
patterns. The future automated capability can follow that evidence.
