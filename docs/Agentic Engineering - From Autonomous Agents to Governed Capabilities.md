Agentic Engineering: From Autonomous Agents to Governed Capabilities

# The curriculum itself is evolving

This might be the most important finding for what you're building.

The **early training market** was basically:

```text
Prompt
→ LLM
→ tool call
→ agent
```

The stronger 2026 curricula increasingly look like:

```text
Architecture
→ reasoning/planning
→ tools
→ state/memory
→ orchestration
→ multi-agent systems
→ human control
→ evaluation
→ security
→ observability
→ deployment
→ operations
→ governance
```

UChicago's curriculum makes this especially explicit with its six themes: **Architecture, Orchestration, Control, Evaluation, Safety & Security, Operations.** ([MPCS Courses][2])

GitHub's certification similarly evaluates architecture, execution environments, state, evaluation, multi-agent coordination and accountability. ([Microsoft Learn][21]) NVIDIA includes architecture, deployment, monitoring, reliability, safety, compliance and human oversight. ([NVIDIA][22])

**That's the move from “AI agent development” to “agentic systems engineering.”**

# And this is where I see the SideFX opening

I found **a lot** of education about building agents.

I found considerably less teaching an overarching, vendor-neutral engineering discipline answering:

> What is the authoritative unit of meaning?

> Where does an agent's authority begin and end?

> How do we separate intent from implementation?

> How do we prevent meaning from becoming trapped in agent code, workflows and prompts?

> How does an autonomous action map back to a business responsibility and expected outcome?

> How do we prove execution rather than merely observe it?

> How do we govern capabilities independently of the particular model, framework or agent performing them?

That is where your curriculum can be materially different.

Your class doesn't have to compete with:

```text
How to use LangGraph
How to use CrewAI
How to build an MCP server
How to configure Claude Code
```

Those are **mechanical skills** worth teaching.

Your higher-level class can teach:

```text
AGENTIC ENGINEERING

Intent
       ↓
Scenario

Input → Event → Outcome
Data  → Action → Experience
       ↓
Authority
       ↓
Agent Responsibility
       ↓
Permitted Tools / Capabilities
       ↓
Execution
       ↓
Testimony
       ↓
Evaluation
       ↓
Governed Outcome
```

That is a proper engineering frame.

And then LangGraph, GitHub, Codex, Claude, MCP, A2A, AWS, NVIDIA, ServiceNow and everything else can become **examples and providers inside the curriculum instead of defining the curriculum.**

## The market position I would claim carefully

I would **not** claim “nobody else teaches agentic engineering.” That is no longer defensible in 2026.

University at Buffalo literally calls its course *Introduction to Agentic Engineering*. UChicago calls theirs *Agentic AI Engineering*. Specialist schools are already appearing with the same terminology. ([CS & Engineering Dept.][1])

But this claim looks defensible from the market scan:

> **Agentic engineering is emerging as a discipline, but its canonical engineering model is still unsettled.**

Some schools center the agent.

Some center frameworks.

Some center cloud platforms.

Some center SDLC automation.

Some center leadership/governance.

There does **not yet appear to be one dominant, vendor-neutral engineering doctrine comparable to what DevOps, SRE or platform engineering eventually developed.**

That is the moment you're entering.
